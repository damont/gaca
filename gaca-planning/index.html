GACA — a Good And Cheap Agent you actually own

A self-hosted personal assistant: an Android app talks through a secure API to a central agent loop on your server. The loop has memory, skills, and tools, spawns subagents (coding, GitHub, calendar), and runs against either a local open-source model or a provider. This is a walk-through of what already exists, what to adopt, what to build, and how to lay out the code.

Your draft, decoded

Here's the rough draft you handed me, and the same idea cleaned up. The architecture you sketched is sound — it's the standard "agent gateway" shape that several 2026 projects converge on. What's missing is mostly the plumbing that makes it safe and swappable: a model gateway, an auth layer, a sandbox boundary, an approval gate for write actions, and a scheduler. The Full GACA Plan works those into the build.

The one-paragraph answer

Recommendation Don't build the agent loop from scratch, and don't adopt a single heavyweight framework either. Build a thin orchestration core you fully understand (a few hundred lines over Pydantic AI or LangGraph), and wrap mature, boring components for everything underneath it: LiteLLM for local↔provider swapping, MCP servers for Google/GitHub, an existing coding CLI (Aider / opencode / Pi) as the coding subagent, Mem0 + sqlite-vec for memory, the open SKILL.md format for skills, and a native Android app (Kotlin + Compose) reaching the API through Cloudflare (Tunnel + Access) as the front-end. The Pi runs the components under Nix + systemd (no Docker); inference points at a provider now and a local GPU box later — a one-line config change. See the Full GACA Plan for the current shape (four components, agent calls tools directly, dedicated memory) — it supersedes specifics on this study page.

What you were missing in the draft

Model gateway

A box between the loop and the model so "local LLM or provider" is a config flip, with fallback. → LiteLLM.

Auth + secrets

The API layer needs auth (single-user API key/JWT) and a vault for OAuth tokens / provider keys.

Sandbox boundary

Subagents and the coding agent run untrusted code. Wrap them in bubblewrap + ephemeral worktrees.

Approval gate

You gave email read-only but calendar/GitHub write. Risky writes should pause for a phone tap.

Scheduler

Your draft is request→response only. A cron loop lets the agent act proactively (briefings, jobs).

Observability

To trust an agent you own, you need a log of every tool call and decision. Build this in from day one.
