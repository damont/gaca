Odysseus workspace

PewDiePie's privacy-first, self-hostable ChatGPT/Claude-app equivalent: chat, autonomous agent mode, a model "Cookbook" that scans your hardware and recommends from ~270 models, deep research, docs, memory, email/calendar/notes. Born from his late-2025 videos running a modded multi-GPU rig and an "AI Council" of personalities that debate and vote.

For GACA: a great reference and possibly a ready front-end — but it's a whole opinionated app, and AGPL-3.0 means network-use copyleft. Mine it for ideas; don't fork it as your core unless you'll open-source everything.

github.com/pewdiepie-archdaemon/odysseus · pewdiepie-archdaemon.github.io/odysseus

Hermes Agent harness

Two things share the name "Hermes" from Nous Research: the model family (Hermes 2/3/4) and — separately — Hermes Agent, a real MIT-licensed, model-agnostic terminal harness that self-improves: it distills "skills" from experience, keeps persistent cross-session memory, has a cron scheduler, and a messaging gateway (Telegram/Discord/Slack/WhatsApp/Signal/Email). Spawns isolated subagents.

For GACA: closest in spirit to what you're describing. Worth studying its skill-learning loop and gateway design. Note it overlaps with OpenClaw (docs even mention migrating between them).

github.com/NousResearch/hermes-agent

OpenClaw gateway

You already use this — your invest skill references a "recurring openclaw job." It's a self-hosted daemon (🦞 "Molty") that connects chat apps you already use to coding agents/LLMs on your hardware, with a Plan → Review → Execute pipeline, per-agent isolated sessions, git-worktree strategy, and a huge channel list. Strong at the "kick off a coding job from Telegram" pattern.

For GACA: a viable off-the-shelf gateway + job-runner if you want to skip building the API/channel layer. Trade-off: local-model support isn't clearly documented (it's built to route to strong hosted coding agents), and it's a big Node codebase to fully "understand."

github.com/openclaw/openclaw · docs.openclaw.ai

Pi coding CLI

Deliberately minimal coding agent: <1k-token system prompt, four tools (read/write/edit/bash), no MCP or permission system by default, extend via packages. Ships reusable TS libs — pi-ai (unified multi-provider LLM API), pi-agent-core (agent runtime), pi-tui. Now under the @earendil-works scope. Active daily (a release shipped today).

For GACA: an excellent coding subagent to shell out to, and its libs are a clean reference for a lean agent loop if you build in TS. Not a gateway and no built-in multi-agent.

github.com/badlogic/pi-mono → earendil-works/pi

Takeaway None of the four is "the answer" by itself, but they map cleanly onto GACA's layers: OpenClaw/Hermes show the gateway+scheduler+skills pattern, Odysseus shows the local-first workspace UI, and Pi (or Aider) is the coding subagent. The decision is how much of the gateway you adopt vs. build — see the verdict at the bottom.

The wider field: agent frameworks

If you want the core handed to you

Letta — loop + server API + self-editing tiered memory + multi-agent, Apache-2.0. The least code to a working stateful agent. Trade-off: opinionated, heavier to "understand fully."

If you want control + understanding

Pydantic AI or LangGraph wrapped in your own FastAPI. You own the loop (the part you care about); they handle model/tool plumbing. Recommended for GACA.

If you want a standard API server

Llama Stack — a self-hosted, OpenAI-compatible agentic server with MCP + RAG built in. Good if you'd rather configure than code.

Memory & Skills — quick calls

Long-term memory

  • Mem0 (Apache-2.0) — the popular drop-in memory layer; cleanest self-host. Pick for personal scale.
  • sqlite-vec — vector search as a single SQLite extension. Trivial on a Pi, no extra service. Pair with Mem0 or use raw.
  • Letta — get memory baked into the loop instead of bolting it on.
  • Chroma / Qdrant — if you outgrow sqlite-vec. Graphiti (not deprecated Zep CE) for temporal knowledge graphs.

Skills ("repeatable defined work")

Your draft's "skills / repeatable context-defined work" box maps exactly onto Anthropic's Agent Skills — an open standard launched Oct 2025: a folder with a SKILL.md (YAML frontmatter + Markdown, optional bundled scripts). It's portable across Claude Code, Codex, Gemini CLI, Cursor, etc.

Pick Implement the open SKILL.md convention in your own loop — it's just a parseable bundle format. No platform lock-in, and you can reuse Anthropic's ~17 open-sourced skills as examples. (You already author skills like invest — same idea.)

So: which path for GACA?

Path A — Adopt a gateway

Run OpenClaw or Hermes Agent as-is; configure skills + MCP + a coding agent. Fastest to working. Cost: a large codebase you didn't write, less of the "understand & control" you want, local-model story varies.

Path B — Thin core over a framework

Build a small FastAPI + Pydantic AI/LangGraph loop; wrap LiteLLM, MCP, a coding CLI, Mem0, SKILL.md. Recommended. Best balance of understanding, control, and not reinventing plumbing.

Path C — Adopt Letta as the core

Use Letta server for loop+memory+subagents+API; you add tools, skills, UI, and the coding subagent. Middle ground — less code than B, more opinionated than B, more "yours" than A.

The Full GACA Plan assumes Path B, but note where Path C (Letta) would slot in instead.
